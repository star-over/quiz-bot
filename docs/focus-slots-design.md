# Focus Slots: drill-ориентированный выбор вопросов

> Дата: 2026-03-28 (обновлено: 2026-05-05)
> Статус: реализовано
> Заменяет: раздел 8 «Три корзины» из bkt-f-implementation-plan.md

## Проблема

Текущий план (раздел 8) проектирует выбор «один вопрос → один KC → следующий KC».
Это паттерн **тестирования** (assessment), а не **обучения** (drill).

Желаемое поведение: за 10–20 мин сессию студент глубоко прорабатывает 3–5 тем, а не поверхностно касается 30. Темы с ошибками доминируют, уверенно знакомые — уходят быстро.

### Структурная проблема BKT-F при поштучном выборе

При строгом приоритетном выборе (один ответ на KC за ревью) known стабилизируется на ~0.83 и **никогда не достигает** порога консолидации 0.95. Причина: Байесовское обновление при known=REVIEW_TARGET(0.50) + LEARN(0.20) имеет математический потолок 0.826.

Drill-подход решает эту проблему естественно: несколько ответов подряд на один KC пробивают потолок.

---

## Концепция: два уровня планирования

```
BKT-F (долгосрочная память)              Focus Slots (краткосрочный drill)
├── known, halfLife per KC                ├── 3–5 KC в фокусе прямо сейчас
├── когда вернуть KC на повторение        ├── correctStreak per slot
├── consolidated навсегда                 ├── какой вопрос показать следующим
└── между взаимодействиями                └── внутри текущего взаимодействия
```

**BKT-F** — без изменений. Обновляется после каждого ответа как сейчас.
**Focus Slots** — новый слой поверх BKT-F, управляющий выбором внутри взаимодействия.

## Focus Slots: структура

### Состояние (новое поле в `users`)

```typescript
focusSlots: v.optional(v.array(v.object({
  kcId:          v.string(),    // какой KC сейчас в фокусе
  role:          v.union(       // роль слота (определяет поведение выхода)
    v.literal("drill"),         // активное изучение / due review
    v.literal("new"),           // новый KC из курикулума
    v.literal("review"),        // ранний повтор / проблемный / reinforcement
  ),
  correctStreak: v.number(),    // правильных подряд (для условия выхода)
  totalAnswers:  v.number(),    // всего ответов на этот KC в этом заходе
  enteredAt:     v.number(),    // timestamp попадания в слот
})))
```

### Параметры

| Параметр | Значение | Обоснование |
|---|---|---|
| Количество слотов | 4 | 2 drill + 1 new + 1 review = ~12 вопросов на полный цикл |
| Streak для выхода | 3 правильных подряд | Достаточно для уверенности, не утомляет |
| Таймаут обновления | 30 мин | Если пользователь вернулся спустя 30+ мин — слоты пересматриваются |
| Порог для нового KC | known ≥ 0.85 | Когда все активные KC выше порога — refill может стать `"new"` |

### Распределение ролей по слотам

```
Слот 1: drill    — активный пул (known < 0.70) или due for review
Слот 2: drill    — активный пул (known < 0.70) или due for review
Слот 3: new      — новый KC из курикулума
Слот 4: review   — ранний повтор, проблемный KC, reinforcement
```

Это обеспечивает баланс в каждом цикле: ~6 вопросов drill + ~3 новое + ~3 повторение.

## Алгоритм: nextQuestion()

```
1. Загрузить focusSlots из users
2. Если нет слотов ИЛИ прошло > 30 мин с последнего ответа → initSlots()
3. Выбрать слот для следующего вопроса:
   a. Среди слотов с correctStreak < EXIT_STREAK — взять слот с min(known)
   b. Если все streak ≥ EXIT_STREAK → kcExit() на самом старом, затем fillSlot()
4. Выбрать случайный вопрос для KC этого слота (через questionKcs index)
5. Показать вопрос, обновить totalAnswers
```

### initSlots() — инициализация/обновление слотов

```
1. Для каждого существующего слота:
   - Вычислить текущий known (с учётом забывания с enteredAt)
   - Если KC consolidated → убрать из слота
   - Если streak ≥ EXIT_STREAK и прошло > 30 мин → убрать (отработан)
   - Иначе оставить (незавершённый drill продолжается)
2. Заполнить пустые слоты через fillSlot() с учётом ролей
```

### fillSlot({ role }) — заполнение одного слота

Для ролей `drill` и `new` — прямой источник. Для `review` — каскад.

**Роль `drill`:**
```
1. Active pool: userMastery WHERE known < 0.70 AND NOT consolidated → min(known)
2. Due for review: userMastery WHERE nextReviewAt ≤ now AND NOT consolidated → max(priority)
3. Fallback → fillSlot({ role: "review" })
```

**Роль `new`:**
```
1. Следующий KC из курикулума (окно 10 после curriculumPointer)
2. Fallback → fillSlot({ role: "review" })
```

**Роль `review` — каскад приоритетов:**
```
Тир 4: Раннее повторение
  userMastery WHERE NOT consolidated AND known ≥ 0.70
  Сортировка: min(known) — самые слабые среди не-due

Тир 5: Проблемные KC
  KC с наибольшим количеством ошибок в answerLog (исторически)
  Не consolidated, давно не практиковались

Тир 6: Свежие KC (углубление)
  lastSeen в последние 7 дней, мало totalAnswers
  Недавно введённые, нуждаются в закреплении

Тир 7: Хрупкие consolidated
  consolidated = true, сортировка по min(halfLife)
  HL=64 более хрупкий чем HL=256

--- граница: выше — полноценное обучение, ниже — maintenance fallback ---

Тир 8 (fallback): Случайный consolidated
  Любой consolidated KC, random
  Только если тиры 4–7 все пусты
  Единственная цель — не оставлять пользователя без вопросов
```

**Инвариант: fillSlot() всегда возвращает KC.** Тир 8 гарантирует непустой результат пока в системе есть хотя бы один KC с вопросами.

## KC Exit: условие выхода из слота

KC покидает слот когда:
1. **correctStreak ≥ 3** — студент продемонстрировал уверенность
2. **consolidated** — KC достиг порога мастерства (known ≥ 0.95 И HL ≥ 64)
3. **Принудительно** — при initSlots() после таймаута 30 мин

При выходе слот заполняется через fillSlot(). Роль выбирается динамически: если все активные (non-consolidated) слоты имеют `known ≥ NEW_KC_KNOWN_THRESHOLD` (0.85), refill получает роль `"new"` и подтягивает свежий KC из курикулума. Иначе сохраняется исходная роль вышедшего слота. Это предотвращает бесконечное кручение consolidated KC в review-слотах.

### Поведение при ошибке

Ошибка сбрасывает correctStreak в 0. KC **остаётся** в слоте. Это ключевое отличие от тестера: ошибка = «продолжаем drill», а не «увидимся через 5 дней».

## Сессии: мягкое определение через таймаут

Явных сессий нет. Вместо этого:

- **< 30 мин** с последнего ответа → продолжение текущих слотов
- **≥ 30 мин** → вызов initSlots():
  - Пересчёт known (забывание за время отсутствия)
  - Удаление отработанных KC
  - Заполнение освободившихся слотов

Это покрывает все паттерны использования:
- **3 вопроса** → слоты сохранены, при возврате через минуту — продолжение
- **20 минут** → слоты постепенно обновляются по мере выхода KC
- **1.5 часа** → много циклов смены KC, естественный прогресс
- **Вернулся на следующий день** → полная перезагрузка слотов

## Путь одного KC (типичный сценарий)

### Сессия 1: первая встреча (KC новый, known=0.10)

```
Вопрос 1: ❌  known 0.10→0.16  HL 1→0.5   streak=0
Вопрос 2: ✅  known 0.16→0.42  HL 0.5→1   streak=1
Вопрос 3: ❌  known 0.42→0.14  HL 1→0.5   streak=0  ← KC остаётся!
Вопрос 4: ✅  known 0.14→0.39  HL 0.5→1   streak=1
Вопрос 5: ✅  known 0.39→0.73  HL 1→2     streak=2
Вопрос 6: ✅  known 0.73→0.93  HL 2→4     streak=3  ← выход из слота

Итого: 6 вопросов, known 0.10 → 0.93, HL=4 дня
```

### Сессия 2: повторение (через 2 дня, known ≈ 0.65)

```
Вопрос 1: ✅  known 0.65→0.90  HL 4→8     streak=1
Вопрос 2: ✅  known 0.90→0.98  HL 8→16    streak=2
Вопрос 3: ✅  known 0.98→0.998 HL 16→32   streak=3  ← выход

Итого: 3 вопроса, known → 0.998, HL=32
```

### Сессия 3: закрепление (через ~5 дней, known ≈ 0.90)

```
Вопрос 1: ✅  known 0.90→0.98  HL 32→64   streak=1
  → known ≥ 0.95 И HL ≥ 64 → CONSOLIDATED ← выход

Итого: 1 вопрос → consolidated
```

**Итого: 10 ответов, 3 сессии, ~7 дней → consolidated.**

## Прогноз: полный курс 368 KC

При drill-подходе:
- KC за сессию: ~4 (один цикл слотов)
- Ответов на KC до consolidation: ~10 (с учётом ошибок)
- Сессий на KC: 2–3 (введение + 1–2 повторения)

| Режим | KC/день | Дней до полного курса |
|---|---|---|
| 10 мин/день (~25 вопросов) | ~3–4 новых | ~3–4 мес |
| 20 мин/день (~50 вопросов) | ~5–7 новых | ~2–3 мес |
| 30 мин/день (~75 вопросов) | ~8–10 новых | ~1.5–2 мес |

С учётом ошибок (~30%): ×1.3–1.5 к срокам.

## Взаимодействие с BKT-F

BKT-F **не меняется**. Focus Slots — слой поверх:

| Аспект | BKT-F | Focus Slots |
|---|---|---|
| Обновление | после каждого ответа | после каждого ответа (streak, totalAnswers) |
| known/halfLife | вычисляет | читает для выбора KC |
| Консолидация | определяет | реагирует (убирает из слота) |
| Расписание (nextReviewAt) | вычисляет | использует для заполнения drill-слотов |
| Приоритет | computePriority() | использует для ранжирования при заполнении |
