# KC: грануляция и дерево знаний

> Дата: 2026-04-12
> Статус: архитектурное решение (принято), реализация — предстоит

Документ фиксирует пересмотр грануляции KC по итогам рецензий сгенерированных вопросов (апрель 2026). Дополняет `bkt-f-implementation-plan.md` (раздел 2 «Таксономия KC»).

---

## Проблема

При рецензии 7 KC (grammar A1) обнаружена системная проблема: LLM-генераторы массово производят вопросы на **прототипический пример** конструкции и игнорируют её подслучаи.

Пример — `grammar/present_time/present_continuous` (78 вопросов):
- ~60 вопросов на утвердительную форму 3-го лица (`she is reading`)
- 1 вопрос на отрицание (`aren't using`)
- 0 вопросов на вопросительную форму (`Is she reading?`)
- 0 вопросов на stative verbs (`*I am thinking it's wrong`)

Результат: BKT-F оценивает `known` по перекошенному банку. Ученик, ответивший на 3 вопроса `she is doing`, получает `known=0.93` и уходит из drill — но может не знать отрицание или правописание `-ing`.

**Причина не в LLM, а в грануляции KC.** Если KC = `present_continuous` (одна конструкция целиком), то «she is reading» и «isn't she reading?» — одинаково валидные вопросы для этого KC. Генератор не обязан покрывать все подслучаи, а BKT-F не различает, на каком подслучае ученик ошибся.

---

## Решение: KC = минимальный отделимый навык

### Критерий грануляции

> **KC — минимальная единица знания, по которой ведётся отдельный BKT-F трек.**
>
> Два навыка — разные KC, если ученик может освоить один и не освоить другой.
> Два навыка — один KC, если освоение одного гарантирует освоение другого.

Тест: «Может ли ученик правильно отвечать на подслучай A и систематически ошибаться на подслучае B?»

- **Да** → A и B — разные KC
- **Нет** → A и B — один KC, разные вопросы

### Примеры применения теста

| A | B | Разделяется? | Решение |
|---|---|---|---|
| `she is reading` (утв.) | `she isn't reading` (отр.) | Да — контаминация с `doesn't read` | Разные KC |
| `she is reading` (утв.) | `he is reading` (утв.) | Нет — та же форма, другое подлежащее | Один KC |
| `is running` (утв.) | `is lying` (ie→y) | Да — разные правила правописания | Разные KC |
| `is reading` (конструкция) | `*I am knowing` (stative) | Да — формирование vs лексическое ограничение | Разные KC |
| `she has got` | `she hasn't got` | Да — контаминация с `she doesn't have` | Разные KC |
| `she has got` | `he has got` | Нет — та же форма | Один KC |

### Что НЕ является основанием для разделения KC

- Разные подлежащие (I/he/she/they) — одна форма, разный контекст
- Разные лексические единицы в одной конструкции — `is reading` vs `is playing`
- Разные маркеры времени — `now` vs `right now` vs `at the moment`
- Разная длина предложения или сложность контекста

Это разнообразие вопросов внутри одного KC, не основание для нового KC.

## Дерево KC

KC организованы в дерево. Уровни:

```
grammar                                              ← категория (агрегат)
  grammar/present_time                               ← тема (агрегат)
    grammar/present_time/present_continuous           ← branch KC (агрегат)
      grammar/present_time/present_continuous/affirm  ← leaf KC (BKT-F трек)
      grammar/present_time/present_continuous/neg     ← leaf KC (BKT-F трек)
      grammar/present_time/present_continuous/spell   ← leaf KC (BKT-F трек)
```

### Leaf KC

- **Единица BKT-F трекинга**: own `known`, `halfLife`, `consolidated`
- Хранится в `userMastery`
- Каждый вопрос привязан к одному leaf KC (primary) и опционально к другим (secondary)
- Для простых KC (простые grammar) — leaf совпадает с branch (нет детей)

### Branch KC

- **Агрегат из leaf-детей**: `branch.known = f(children.known)`
- Не хранит own `known` — всегда computed view
- Используется для:
  - **Курикулум**: sortOrder, прогресс, «следующая тема»
  - **Focus Slots**: слот = branch KC, nextQuestion выбирает слабейший лист
  - **UI**: показать пользователю «Present Continuous — 73%»
- `consolidated(branch)` = все leaf-дети consolidated

### Простые KC (leaf = branch)

Не все KC нуждаются в дроблении. `grammar/modality/can_ability` — один навык без подслучаев. Такой KC одновременно leaf и branch: имеет BKT-F трек и участвует в курикулуме напрямую.

```
grammar                      ← категория
  grammar/modality/can_ability  ← leaf KC (сам себе branch, BKT-F трек)
```

## Cross-pollination между сиблингами

При ответе на leaf KC сиблинги получают вторичное обновление через существующий механизм `SECONDARY_LEARN_FACTOR`.

```
Вопрос на present_continuous/affirm:
  primary:   present_continuous/affirm  → LEARN × 1.0
  secondary: present_continuous/neg     → LEARN × SECONDARY_LEARN_FACTOR
  secondary: present_continuous/spell   → LEARN × SECONDARY_LEARN_FACTOR
```

Обоснование: leaf KC внутри одного branch разделяют общую базу (конструкция `am/is/are + -ing`). Правильный ответ на утверждение частично подтверждает знание отрицания. Но для consolidation нужна прямая практика на каждом leaf.

На старте — одинаковый вес для всех сиблингов. Калибровка по данным — после накопления ответов.

## Влияние на Focus Slots

Текущий дизайн (из `focus-slots-design.md`):

```
Слот берёт KC → показывает случайный вопрос → streak=3 → exit
```

Новый дизайн:

```
Слот берёт BRANCH KC → выбирает слабейший LEAF внутри → показывает вопрос на этот leaf
```

При ошибке: повторяет тот же leaf (drill на слабом месте).
При streak=3 на leaf: переключается на следующий слабейший leaf в том же branch.
При consolidated(branch): exit из слота.

Это решает исходную проблему: ошибка на отрицании → drill на отрицании, а не на случайном вопросе из branch.

---

## Влияние на курикулум

- `sortOrder` — по branch KC (как сейчас, ~368 записей)
- Прогресс пользователя — по branch KC
- Курикулум вводит branch KC, внутри которого ученик проходит все leaf KC

---

## Влияние на BKT-F

Алгоритм BKT-F (`bktPure.ts`) **не меняется**. Изменения:

- `userMastery` хранит записи per leaf KC (вместо per branch KC)
- Cross-pollination использует существующий `SECONDARY_LEARN_FACTOR`
- Коэффициенты (LEARN, PRIOR, пороги) потребуют рекалибровки при увеличении числа leaf KC — чтобы общее время обучения оставалось в разумных пределах

---

## Влияние на генерацию вопросов

- Каждый вопрос привязан к leaf KC (поле `kcs[]`)
- Промпт генерации получает конкретный leaf KC как задание
- Рецензия проверяет покрытие: у каждого leaf KC должно быть достаточно вопросов
- Проблема «78 вопросов на one is doing» исчезает: генерация идёт per leaf, а не per branch

---

## Понятие «Аспект»

В процессе анализа использовался термин «аспект KC» как промежуточное понятие. В финальном дизайне **аспекты не существуют как отдельная сущность**.

То, что называлось «аспектом», стало leaf KC — полноценной единицей BKT-F трекинга с собственным `known`.

> Если при обсуждении или рецензии возникает «аспект, который не покрыт» — это сигнал к созданию нового leaf KC, а не к добавлению метаданных.

## Миграция

1. **kc-catalog.jsonl** — branch KC остаются как есть. Leaf KC добавляются как новые записи с kcId вида `branch_kc_id/leaf_name`. Простые KC (простые grammar) не дробятся.
2. **userMastery** — полная перезапись допустима. При дроблении branch KC на leaf: начальное known leaf = known branch × коэффициент (или PRIOR для новых leaf).
3. **seed/questions.json** — поле `kcs[]` обновляется: вместо branch KC указывается конкретный leaf KC.
4. **Схема** (`convex/schema.ts`, `seed/schemas.ts`) — без структурных изменений. Leaf KC — обычные записи в `kcCatalog` и `questionKcs`. Дерево выводится из формата kcId (`/`-разделитель).

## Открытые вопросы

- **Рекалибровка BKT-F**: при увеличении числа leaf KC нужно пересмотреть LEARN, EXIT_STREAK и пороги консолидации, чтобы общее время обучения не выросло непропорционально
- **Формула агрегации branch.known**: простое среднее по leaf-детям, или взвешенное (по количеству ответов, по важности leaf)?
- **Какие grammar KC дробить первыми**: начать с 9 KC уровня A1, у которых есть рецензии и данные о дефицитах
- **Stative verbs**: отдельный branch KC (`grammar/present_time/stative_verbs`) или leaf внутри `present_continuous`? По тесту отделимости — скорее отдельный branch, т.к. stative verbs влияют на все Continuous-времена, не только Present
