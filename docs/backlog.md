# Бэклог

## Задержка перед следующим вопросом

**Статус:** отложено
**Дата:** 2026-03-22
**Связано с:** напоминания, периодическое обучение, контроль темпа

### Проблема

Следующий вопрос приходит сразу после фидбека. Пользователь не успевает изучить объяснение.

### Загрязнение данных

`shownAt → respondedAt` измеряет время на вопрос. Если фидбек и следующий вопрос видны одновременно, пользователь тратит часть этого времени на чтение фидбека — данные для IRT-калибровки контаминируются. Нет способа разделить «думал над вопросом» и «изучал фидбек на предыдущий».

### Техническое решение

Convex `ctx.scheduler.runAfter()`. Задержку делать динамической (по длине explanation). Нужен отдельный `internalAction` с собственным grammY `Api` инстансом, хранение `scheduledId` для отмены при `/start`, `/stop`, `/test`.

### Почему отложено

- Фидбек остаётся в чате (не пропадает), проблема скорее в ощущении
- Нет данных о реальном поведении пользователей
- Реализация добавляет ~100 строк + schema change + race condition handling
- Логически относится к тому же блоку что напоминания и периодическое обучение
